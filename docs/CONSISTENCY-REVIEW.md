# Phase 1 三文档一致性审查

- 审查日期：2026-10-26
- 审查人：项目总监（大湾区靓仔）
- 输入：`PRD.md`、`ARCHITECTURE.md`、`UIUX.md`、`openapi.yaml`、`ADR-001` 至 `ADR-005`、`OPEN-DECISIONS.md`
- 说明：两位专家在产出文件后因 429 频率限制中断，以下结论基于已落盘文件的独立交叉审查，不代表专家已回传最终 verdict。

## 1. 结论

三份文档整体方向一致：保留 Manifest V3 原生扩展、Service Worker 直连官方 Gemini API、BYOK 会话保存、摘要/安全审查/翻译三模式、离线演示必须显著标注、Lucide 本地 SVG、无后端/无自建代理。

**可以进入 Spec 编制**，但必须先确定下面两项范围冲突。未决项不解决，Spec 会把矛盾写进开发契约。

## 2. 用户已确认的决策（2026-10-26 锁定）

| 冲突 | 用户决策 | 锁定值 |
|---|---|---|
| 输入上限 | 1 万字符 | **10,000 字符**，以 JavaScript `.length`（UTF-16 code units）计数，trim 后判断 |
| Key 持久化 | 后续版本再做 | **仅 session**（`chrome.storage.session`），MVP 不提供"记住我" |
| 日志 | 不记录，脱敏 | **生产默认零持久日志**；仅开发/测试模式可输出脱敏诊断（不含原文、Key、完整响应） |

架构文档中"12,000 UTF-16"与"可选 local 持久化"两条描述已被上述决策覆盖，Spec 为最终权威。

## 3. 已对齐项

- 模式范围：摘要、安全审查、翻译，不做整页抓取、PDF/OCR、多模型、账户、历史记录。
- 数据边界：仅用户主动提交的选中文本；不读取浏览历史；不发送密码、密钥、身份证件等敏感信息。
- 失败处理：缺少 Key、401、403、限流、超时、网络、格式异常分开提示，不显示固定“分析完成”假象。
- 演示模式：离线固定样例必须显示“离线演示，非 Gemini API 结果”，不得计入真实 API 验收。
- 图标：Lucide 本地静态 SVG，禁止 emoji 功能图标和紫粉渐变。
- API：`POST /v1beta/interactions`，`Api-Revision: 2026-05-20`，`store=false`、`stream=false`；真实模型仍待 OPEN-001/OPEN-002 验证。

## 4. 外部阻塞，不因文档确认而关闭

- **OPEN-001**：当前 Google Cloud 项目是否具备免费层推理资格，尚无真实请求证据。
- **OPEN-002**：默认模型尚未实测，`gemini-3.8-flash` 只能作为候选。

3. 进入 Phase 1.5 Spec 编制。
4. 之后再进入设计细化和开发；当前不修改 `D:\gemini-summary-ext`。
