# ADR-004: 保留原生 JavaScript 并建立两层自动化测试

## Status: Accepted (2026-10-26)

## Background

现有扩展无框架、无构建步骤、无测试。引入 SPA 框架和打包器会增加学习及维护成本，却不会改善三个简单模式的核心能力。真实 API 当前受项目资格限制，测试必须默认离线可复现，不能把 Mock 当真实成功。本机已有 Node.js 22.22.2；Playwright 官方支持以 persistent Chromium 测试 MV3 扩展。

## Decision

运行时使用原生 HTML/CSS/JavaScript ES modules，不增加运行时 npm 依赖。纯逻辑使用 Node `node:test`，浏览器集成使用精确版本 `@playwright/test@1.64.1`，package-lock 固定依赖树。默认测试通过 fake fetch 和网络 route 使用虚构 Key；真实 API 测试独立且默认跳过，只有用户本机显式启用才运行。

## Consequences

正面：保留现有简单结构；安装后直接加载扩展；核心失败路径可重复测试；CI 不需要真实 Key；浏览器测试覆盖 Service Worker 和 popup。

负面：需要手写少量 DOM 和消息代码；原生系统右键菜单仍需人工冒烟；Playwright 是开发依赖并需下载 Chromium。
